# SkyTrace UX rework — 4 October 2026

Base: `79c8610` (main). Scope: FR24-style layout, smoother selection, new features.

## What was reproduced first

- Selecting an aircraft ran `flyTo(position)` after 280 ms, then `flyToBounds(route)` as soon as the track arrived: two competing camera moves and a zoom-out of up to several levels. The route fit measured the drawer while it was still animating in.
- The selected flight object was a snapshot taken at click time, so altitude and speed in the drawer froze while the aircraft kept flying.
- Markers jumped to the new coordinates on every poll.
- The drawer was re-mounted with `AnimatePresence mode="wait"` when switching aircraft, so a new selection waited for the exit animation.

## Measured after the change (Chromium, 1440×900, synthetic traffic)

- Selecting an aircraft that is off screen: one eased pan (translate 0 → 381 → 647 → 722 → 784 → 801 → 803 px over about 0.6 s), then no further movement while the route arrives. Selecting one already on screen: the map does not move.
- Aircraft DOM mutations at rest with no speed data: still 0 over 2.2 s (existing regression test). With speed and heading, each marker is updated once per second.

## Checks run

- `npx tsc -b`, `npx eslint .`: clean.
- `npx vitest run`: 64 tests (new: dead reckoning, filters, units, search, topbar).
- Playwright against the local app with mocked APIs: 38 tests pass (Chromium desktop and a Pixel 5 emulation). Firefox and WebKit were not run: only Chromium is installed here.
- Python tests were not touched by this change.

## Limits

- The capture environment had no internet access. Screenshots use a synthetic API, a procedural base map and a placeholder aircraft photo. Real tile contrast, real ADS-B traffic density and the production Vercel functions were not exercised here.
- Dead reckoning assumes the feed's `time_position`/`last_contact` are in the same clock as the browser; a badly skewed device clock would shift positions by the skew times the speed (capped at 90 s).
- The phone layout was checked on one emulated viewport only.
