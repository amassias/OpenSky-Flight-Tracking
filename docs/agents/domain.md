# Domain docs

## Before exploring

Read `CONTEXT.md` for existing project vocabulary.
Read root `GLOSSARY.md` when present, and the ADRs in `docs/adr/`
relevant to the work.

If the glossary is absent, proceed silently. The domain-modeling
skill creates it when terms are resolved.

## Layout

This repo uses a single context:

- `GLOSSARY.md`: domain vocabulary
- `docs/adr/`: architectural decisions

## Vocabulary and decisions

Use glossary terms consistently in issues, proposals and test names.
If CONTEXT.md and the glossary conflict, surface the discrepancy.

Flag any proposal that contradicts an existing ADR, name that ADR,
and explain why the decision should be reconsidered.
